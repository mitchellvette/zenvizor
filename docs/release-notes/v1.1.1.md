First patch release. Fixes service startup behaviour, the start-minimized-to-tray path, and adds an in-app way to start or restart the service without dropping to an admin terminal.

ZenVizor remains a lightweight, **passive** Windows network monitor: it attributes outbound and inbound traffic to the originating process (including svchost-hosted service names), stores tiered history locally in SQLite under user-configurable retention, surfaces a near-live dashboard with local alerts, produces daily reports, and emits **zero network traffic of its own**, verified end-to-end via the self-monitoring gate on every release.

## What's fixed in 1.1.1

- **The service now starts automatically with Windows.** Previously you had to start it yourself after every reboot, and the UI would show "Service Disconnected" until you did. New installs and upgrades default to auto-start.

- **"Start minimized to tray" actually works.** Before, turning on this setting left a small strip of window chrome at the bottom-left of the screen instead of hiding the window properly. Now the window goes straight to the tray on launch, and clicking the tray icon brings it back.

- **Alert notifications work when you start straight to the tray.** Previously, if you launched ZenVizor into the tray without ever opening the window, background activity — including alert notifications — wouldn't run until you opened the window once. Now they run from launch regardless of whether the window is visible.

- **The "Start with Windows" setting reports its real state.** In an edge case where ZenVizor couldn't read the service's startup mode, the toggle would display ON when it might not be. It now displays OFF in that case, which is honest about the uncertainty.

- **Restart the service from inside the app.** A new button in Settings → Service that asks for admin approval (one Windows prompt) and starts or restarts the service for you. When the service is down, the same button reads "Start service" — so you no longer need to know `sc.exe` to recover from a stopped service.

- **Settings reconnects cleanly after a service restart.** Previously the page would get stuck on the disconnect banner after the service came back up, until you navigated away and back. Fixed.

## No breaking changes

No IPC contract change. No DB schema change. No config-layout change. `zvctl` is unchanged. Existing automation and data carry over without intervention. See [`docs/versioning.md`](https://github.com/mitchellvette/zenvizor/blob/v1.1.1/docs/versioning.md) for the policy.

## Upgrading from 1.1.0

In-place upgrade. Download **`ZenVizorSetup.exe`** below and run it on a machine that already has 1.1.0 installed; Windows Installer will swap the installation in place (same `UpgradeCode`) and your existing `%ProgramData%\ZenVizor\zenvizor.db` history and settings carry forward unchanged. The service will restart as part of the upgrade; the UI re-launches automatically.

> **If you previously set "Start with Windows" to OFF in Settings**, you may want to check that setting again after upgrading. The new install default is ON, and the upgrade re-runs the service registration with the new default. You can confirm the current state via `sc.exe qc ZenVizor` from an elevated terminal (look for `START_TYPE: 2 AUTO_START`), or just open Settings → Service and re-toggle as needed.

## Install (new users)

Download **`ZenVizorSetup.exe`** below and run it. The bundle:

- Detects whether the .NET 10 Desktop Runtime is already installed; installs it silently (from the embedded payload) if missing.
- Installs the ZenVizor Windows Service, the WPF dashboard, and the `zvctl` CLI.
- Creates the data directory at `%ProgramData%\ZenVizor\`, ACL'd to SYSTEM + Administrators.

Total install footprint ≈ 55 MB under `%ProgramFiles%\ZenVizor\` (plus the shared .NET runtime in its standard location).

## System requirements

- Windows 10 or 11, x64.
- Administrator privileges to install (the service runs as `LocalSystem`); day-to-day UI use is non-elevated.

## Files in this release

- `ZenVizorSetup.exe` | the canonical install bundle (~74 MB; embeds the .NET 10 runtime for offline installability).
- `ZenVizor.msi` | the inner MSI for advanced users / silent deployment automation. Most users want the bundle.
- `SHA256SUMS.txt` | SHA256 hashes for the binaries above, attached for offline verification.
