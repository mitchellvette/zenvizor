First post-MVP feature release. Epic A — **History click-to-attribute** — turns the History chart into an actionable surface, and the Per-App and App Detail pages now accept arbitrary `from/to` time windows in addition to the rolling presets.

ZenVizor remains a lightweight, **passive** Windows network monitor: it attributes outbound and inbound traffic to the originating process (including svchost-hosted service names), stores tiered history locally in SQLite under user-configurable retention, surfaces a near-live dashboard with local alerts, produces daily reports, and emits **zero network traffic of its own**, verified end-to-end via the self-monitoring gate on every release.

## What's new in 1.1.0

- **Click on the History chart to see what was happening.** Wherever you click, a small panel shows the top apps active at that point in time and how much data each one was moving. Click an app row to open its detail page already filtered to that time; click "+N more" for the full list. On the 1-hour view the lookup considers a few minutes around your click so a short spike still surfaces the apps responsible for it.

- **Pick any time range on the Per-App and App Detail pages.** The window menu now has a "Custom range…" option that lets you choose a specific from/to date and time. The range you picked stays visible next to the menu so you always know what you're looking at.

- **Text is crisper everywhere.** Small labels (the little uppercase headings on cards, app names and paths in tables, the short descriptions under KPI numbers) now render sharply in both Light and Dark modes.

- **Settings → Alert thresholds got a polish pass.** The three threshold inputs are wider so larger numbers don't get clipped, the small "X" that could wipe out your value in one click is gone, and typing a number above the maximum now snaps to the maximum instead of refusing your input.

- **The "peak" label on the Reports page chart** no longer goes slightly fuzzy depending on where the peak falls.

## No breaking changes

No IPC contract change (the History popover reuses the existing `GetAppListAsync` method). No DB schema change. No config-layout change. `zvctl` is unchanged. Existing automation and data carry over without intervention. See [`docs/versioning.md`](https://github.com/mitchellvette/zenvizor/blob/v1.1.0/docs/versioning.md) for the policy.

## Upgrading from 1.0.0

In-place upgrade. Download **`ZenVizorSetup.exe`** below and run it on a machine that already has 1.0.0 installed; Windows Installer will swap the installation in place (same `UpgradeCode`) and your existing `%ProgramData%\ZenVizor\zenvizor.db` history and settings carry forward unchanged. The service will restart as part of the upgrade; the UI re-launches automatically.

## Install (new users)

Download **`ZenVizorSetup.exe`** below and run it. The bundle:

- Detects whether the .NET 10 Desktop Runtime is already installed; installs it silently (from the embedded payload) if missing.
- Installs the ZenVizor Windows Service, the WPF dashboard, and the `zvctl` CLI.
- Creates the data directory at `%ProgramData%\ZenVizor\`, ACL'd to SYSTEM + Administrators.

Total install footprint ≈ 55 MB under `%ProgramFiles%\ZenVizor\` (plus the shared .NET runtime in its standard location).

## System requirements

- Windows 10 or 11, x64.
- Administrator privileges to install (the service runs as `LocalSystem`); day-to-day UI use is non-elevated.

## Files in this release

- `ZenVizorSetup.exe` | the canonical install bundle (~74 MB; embeds the .NET 10 runtime for offline installability).
- `ZenVizor.msi` | the inner MSI for advanced users / silent deployment automation. Most users want the bundle.
- `SHA256SUMS.txt` | SHA256 hashes for the binaries above, attached for offline verification.
